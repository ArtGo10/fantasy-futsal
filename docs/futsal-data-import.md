# Futsal Data Import

Первый слой импорта для украинской Extra-liga забирает данные из публичных источников лиги, сейчас в первую очередь с официального сайта `futsal.com.ua`, в локальный staging JSON. Для будущих лиг источник может отличаться. Импорт не пишет напрямую в Convex: сначала смотрим качество данных, предупреждения и ручные расхождения.

## Запуск

```sh
npm run data:futsal
```

По умолчанию файл сохраняется сюда:

```txt
data/futsal/source-2026-27.json
```

Можно указать другой путь:

```sh
npm run data:futsal -- --out data/futsal/source-2026-27.local.json
```

## Что импортируется

- сезон `Українська Екстра-ліга 2026/27`;
- 10 команд из таблицы `ekstra-liha-2026-27`;
- составы команд из SportsPress `lists`;
- fallback-поиск игроков по `current_teams`, если игрок не попал в список команды;
- позиции игроков: `Воротар -> goalkeeper`, `Універсал -> universal`;
- фото игроков и логотипы команд через `wp/v2/media`;
- опубликованные матчи Экстра-лиги 2026/27;
- базовая статистика прошлого сезона из таблиц бомбардиров и ассистентов;
- черновая рекомендованная цена игрока на базе прошлогодней статистики.

## Почему нужен staging JSON

На сайте есть неидеальные данные. Например, игрок может оставаться в старом списке команды, но уже иметь новый `current_teams`. Поэтому скрипт пишет блок `warnings`, где видны:

- команда без списка игроков;
- игрок найден только через fallback по текущей команде;
- игрок есть в нескольких составах;
- список команды и `current_teams` не совпадают;
- у игрока нет фото;
- у игрока нет распознанной позиции.

После ручной проверки staging JSON можно будет загрузить в Convex отдельной админской mutation.

## Загрузка в Convex

Для записи staging JSON в Convex есть админская mutation `futsalImport:importSource` и обертка-скрипт:

```sh
npm run data:futsal:import:dry -- --admin-subject user_...
```

По умолчанию это dry-run: данные не записываются. Для реальной записи:

```sh
npm run data:futsal:import -- --admin-subject user_...
```

Чтобы не передавать Clerk id руками каждый раз, можно положить его в локальный env:

```txt
IMPORT_ADMIN_SUBJECT=user_...
IMPORT_ADMIN_EMAIL=admin@example.com
```

Mutation всё равно проверяет админа на стороне Convex. Сейчас админом считается пользователь с `participantNumber: 1`, либо email/Clerk id из `ADMIN_EMAILS` / `ADMIN_CLERK_IDS`.

По умолчанию импорт помечает отсутствующие в новом источнике команды как неактивные, а игроков как `left`. Если нужно только добавить/обновить найденное и не трогать отсутствующих:

```sh
npm run data:futsal:import -- --keep-missing
```
